# TUOBA Restaurant OS — نظام تشغيل المطاعم المتكامل

نظام تشغيل مطاعم (نموذج أولي تفاعلي) في تطبيق ويب واحد خفيف — بدون خدمات خلفية أو خطوات بناء — يجمع:

- **التشغيل:** POS / طلبات / شاشة المطبخ KDS / الاستلام / الدليفري / الكول سنتر
- **المال:** مركز مالية (P&L للفرع والبراند) / تدفق نقدي / مصروفات بإيصالات مصوّرة / ريسيبي مع ذكاء الهوامش / استيراد Geidea CSV
- **الموارد البشرية:** حضور وانصراف بحساب ساعات وعمل إضافي فعلي حسب الورديات
- **المدفوعات:** NFC / QR / كاش / فيزا / محفظة / تقسيم
- **الأمان:** سجلات تدقيق للعمليات الحساسة + فصل بيانات البراندات والفروع + Passkey (محاكاة)
- **واجهة بـ 5 لغات:** العربية (RTL) وEnglish وFrançais وEspañol وTürkçe — مع تنسيق عملة محلي

## التشغيل

لا توجد أي خطوات بناء. اختر أحد الخيارات:

```bash
# 1) مباشرة: افتح index.html في المتصفح

# 2) أو خادم محلي (يُفعّل الـ PWA والعمل دون اتصال):
python3 -m http.server 8080     # ثم افتح http://localhost:8080
# أو
npx serve .
```

التطبيق **PWA قابل للتثبيت** (أيقونات 192/512 + maskable) ويعمل دون اتصال عبر Service Worker باستراتيجية network-first (التحديثات تصل فورًا، والكاش للطوارئ فقط).

## بنية المشروع

```
index.html          الواجهة + CSP صارم (بدون أي سكربت inline)
style.css           التصميم (متجاوب: موبايل + تابلت)
manifest.webmanifest | sw.js      إعدادات PWA والتخزين دون اتصال
js/
  i18n.js           قاموس الترجمة (5 لغات — parity مُختبَر آليًا)
  state.js          الحالة + هجرة المخطط (Schema migration) + بيانات النطاق
  ui.js             أدوات آمنة: escaping، عملة Intl، toasts، لغة
  tabs.js           شاشات النظام الـ17 + الإجراءات (Event delegation بدل onclick)
  app.js            الإقلاع والربط
icons/              أيقونات التطبيق
tests/smoke.test.js اختبارات دخان وانحدار (تُقلع التطبيق كاملًا في VM)
.github/workflows/  CI: فحص صياغة + اختبارات على كل push
```

## أبرز ما في الإصدار v2 (إعادة الهيكلة الشاملة)

| المجال | ما تم |
|---|---|
| الأمان | ترميز HTML لكل مدخلات المستخدم وملفات CSV (إغلاق XSS) + CSP بدون unsafe-inline + زر مسح بيانات بتأكيد خطوتين |
| صحة البيانات | حقول الدليفري لا تُمحى عند التعديل · السلة تُصفّر عند تغيير البراند/الفرع · طاولات مستقلة لكل فرع · أرقام طلبات/معاملات تسلسلية فريدة |
| HR | حساب ساعات العمل الفعلي من الطوابع الزمنية ISO + احتساب العَمل الإضافي مقابل مدة الوردية + منع حضور مزدوج |
| الاستيراد | محلل CSV وفق RFC (أسطر جديدة وفواصل داخل الاقتباسات) + تحليل مبالغ متعدد الصيغ (1,234.56 و1.234,56) + سجل استيرادات + تدقيق أمني |
| المالية | P&L يدمج مبيعات Geidea + POS + المدفوعات اليدوية، والتكاليف تشمل المصروفات الفعلية |
| الترجمة | اكتمال ~130 مفتاحًا في اللغات الخمس مع اختبار parity آلي |
| PWA | أيقونات كاملة + maskable + favicon + تحديث كاش مُدار + روابط مباشرة (#pos, #kds) |
| الجودة | تقسيم لـ5 وحدات + اختبارات `node --test` + CI على GitHub Actions |

## الاختبارات

```bash
npm install        # مرّة واحدة فقط (جزيئات الاختبار: jsdom)
npm run ci         # فحص صياغة + اختبارات وحدة + اختبار DOM شامل
```

- `tests/smoke.test.js` — 11 اختبار وحدة/انحدار (تُقلع التطبيق كاملًا في VM: الترجمة، CSV، الهجرة، المالية، XSS…)
- `tests/e2e.dom.js` — 30 فحص سيناريو حقيقي في DOM كامل (jsdom): الدليفري، السلة، الطاولات، الحضور، الدفع…

## ملاحظة
